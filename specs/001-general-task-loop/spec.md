# Спецификация General Task Loop

## Сценарии

### US1. Согласовать задачу по этапам (P1)

Пользователь вызывает `my-task-loop` с ключом и описанием или ссылкой. Агент фиксирует решения, собирает постановку и спеку, реализует согласованный объём, проводит ревью и приёмку. Между этапами агент ждёт явную команду.

**Проверка.** После разбора дать замечание. Агент обновляет решения и остаётся на разборе. После команды продолжить переходит к постановке. У принятой постановки есть путь до `tasks.md` как при установленной интеграции Spec Kit, так и при её отсутствии.

### US2. Делегировать реализацию (P1)

Пользователь вызывает `sam-reshu`. Агент согласует результат и допустимые внешние действия, составляет план, реализует и проверяет задачу. Если публикация согласована, агент доводит свою ветку и PR/MR до доступного результата CI.

**Проверка.** Подтвердить исходный объём без push. Агент проводит локальные проверки и возвращает их результат. Если появляется необходимость выйти за согласованную область, агент фиксирует причину и завершает независимые пункты.

### US3. Передать работу (P2)

Пользователь продолжает задачу в другой сессии Claude Code или Codex, либо явно переключает скилл. Получатель сверяет состояние с веткой и артефактами, затем продолжает с подходящего шага.

**Проверка.** Передать ключ, файл состояния и ветку после разбора. Получатель восстанавливает решения и следующий шаг. Авторизация одного действия не расширяется при передаче.

## Требования

- **FR-001.** В пакете две явно вызываемые команды с инструкциями по установке в обоих клиентах.
- **FR-002.** Цикл с переходами охватывает постановку, Spec Kit, реализацию, проверки, ревью и отчёт.
- **FR-003.** Самостоятельный цикл использует компактный план и ограничивает внешние изменения согласованными действиями.
- **FR-004.** Оба цикла используют один формат локального состояния. Переход между ними записывается явно и сохраняет результаты.
- **FR-005.** Публичный пакет включает README и документы передачи разработки. Локальное состояние реальных задач и исходные рабочие материалы хранятся вне пакета.

## Граничные случаи

- Ключи двух репозиториев совпадают. Разные идентификаторы проектов дают разные пути состояния.
- Домашний каталог недоступен для записи. Агент сообщает путь к доступному локальному файлу, который можно передать явно.
- Репозиторий не использует CI или стенд. Итог отражает фактические проверки и конкретную причину отсутствия остальных.

## Критерии успеха

- **SC-001.** Оба клиента обнаруживают `my-task-loop` и `sam-reshu` из установленного пакета.
- **SC-002.** Все ссылки из README и скиллов разрешаются в документ или раздел.
- **SC-003.** Сценарии US1–US3 можно пройти по инструкциям со всеми указанными входами и результатами.
- **SC-004.** Опубликованное дерево совпадает с проверенным списком файлов релиза.
