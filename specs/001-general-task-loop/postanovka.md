# Два скилла для задач в Claude Code и Codex

## Контекст и цель

В разработке небольшую задачу удобно делегировать целиком. Задачу с несколькими решениями удобнее принимать по этапам, чтобы правки к постановке не пришлось вносить после реализации. Обоим сценариям нужен способ продолжить работу после смены сессии или агента.

## Объём и решения

- `my-task-loop` проводит от разбора до отчёта. Пользователь принимает решения и подтверждает переходы. Принятая постановка становится входом для спеки Spec Kit.
- `sam-reshu` согласует объём и критерии в начале, затем ведёт реализацию, самоприёмку и согласованный PR/MR. Пользователь подключается при существенном изменении объёма или блокере.
- Оба скилла используют правила целевого репозитория и общий локальный файл состояния. Пакет устанавливается в Claude Code и Codex из одного набора файлов.

## Критерии приёмки

- Из README можно установить оба скилла и выбрать сценарий по размеру задачи и нужному уровню контроля.
- `my-task-loop` требует подтверждения переходов и описывает прохождение со Spec Kit и без установленной интеграции.
- `sam-reshu` задаёт условия самостоятельного продолжения, публикации PR/MR и обращения к пользователю.
- Новая сессия может найти шаг, решения, артефакты, действующие разрешения и следующее действие по `state.md`.
- В публикуемом дереве находятся только файлы пакета и его спецификация. Примеры используют вымышленные данные.
